# PMS-R1 canonical revalidation: PMS, Front Desk, Guest Ledger, Folio, Cashiering

**Status:** audit and next-package recommendation for independent review; no runtime or operational activation. **Contract:** IVORQ Package Execution Contract v1.22. **Master domain:** MPD-PMS, P1. **Audit base:** `ivorq-enterprise-core` `7bd1eded57e310fda31f427e74c65d1c165f95c4`, tree `ac1567c03bbe1bab608506314e0e3002072b2f4c`.

## Executive determination and evidence discipline

PMS is **ACCEPTED_PARTIAL**. The accepted Front Desk arrival, departure, terminal checkout, Guest Ledger, and General Cashier package trains are substantial and must be preserved. Older PMS CRUD, check-in/out, and folio-close routes still coexist with those controlled boundaries. Reservation commerce, rate calculation, guest lifecycle, and operational workspaces are incomplete. The next implementable package should establish Property-scoped reservation/guest command authority and contain overlapping legacy paths before extending commercial policy. No PMS runtime package is activated here.

`SOURCE_PROVEN` means the cited current code/schema exists; `TEST_PROVEN` means a committed focused test exercises it; `GOVERNANCE_PROVEN` means an accepted ADR/package records authority; `DOCUMENTATION_ONLY` means a PRD or historical plan without matching current command; `INFERENCE` marks a gap or package choice derived from the cited inspection. A table name or UI page alone is never proof of an operational workflow. The historical FD-B13 `CHECKOUT_EXECUTION_BLOCKED_BY_PREREQUISITES` verdict predates Approved ADR-089 and accepted Package 9; current `FrontDeskCheckoutExecutionService` and its tests prove checkout execution exists. The Master Domain Registry's MPD-PMS row selects PMS-R1 but its older prose is not a current runtime verdict.

Path keys in the matrix expand exactly: `P` = `Modules/Operations/PMS`; `FD` = `Modules/Operations/FrontDesk`; `GC` = `Modules/Operations/GeneralCashier`; `FGC` = `Modules/Finance/GeneralCashier`; `T` = `tests/Postgres/Operations`; `UI` = `resources/js/Pages`. `A0` in every row means source audit only: no production/live or operational activation is authorized. A dash in the test column means no focused proof was identified for that specific full capability, not that no tests exist anywhere. `P1`, `P2`, and `P3` in the consequence column refer to the proposed packages below, not to implemented work.

## Cross-cutting gaps, ownership and governance

1. **Legacy overlap:** `P/Services/FrontDeskService.php` still writes legacy `stays` and reservation checkout while `FD/Services/FrontDeskCheckoutExecutionService.php` owns accepted terminal `front_desk_stays` checkout. `P/Services/FolioService.php` delegates open/post/void-item to GLF-A but retains legacy folio close/void. Containment and compatibility need a deliberate P1 plan, not a silent deletion. The old FD-B13 readiness review is historical, not current checkout status.
2. **Property and actor authority:** `P/routes/web.php` applies `web,auth`; legacy repositories call model queries without explicit Property parameters, and `BelongsToProperty` applies a scope only if a current Property ID is available. Controllers/policies add some checks, but the full route → request → service → query chain needs SEC-P01-compatible negative proofs, including active membership, canonical Property mismatch, cross-Company lookup and direct-service bypass. The controlled FD/GLF/GC paths have stronger property-scoped services and tests; this finding does not reopen them.
3. **Commercial inventory:** `AvailabilityService` counts active rooms, overlapping reservations and PMS room blocks by type/date, without an explicit Property input or a locked commitment. Housekeeping owns room readiness, Engineering owns maintenance availability, and physical Inventory owns stock, not hotel sellable rooms. Rate plans are records, not complete pricing/guarantee/group workflows. New overbooking, guarantee, package and rate rules require explicit hospitality policy authority before implementation.
4. **Financial boundary:** GLF-E and GC-A2 are read-only transaction attestations for accepted checkout, not general posting or cashier-close substitutes. PMS owns folio/payment source effects, while Accounting/AR, GL, Tax, Banking, Treasury and Financial Period remain Finance-owned. P3 may consume those contracts; it may not duplicate ledgers or post accounting entries.
5. **Privacy and deferred scope:** ADR-031 is Proposed; guest ID, contact and history fields exist but enterprise classification, masking, retention, legal hold, residency and deletion workflow are `BLOCKED_BY_ADR`. ADR-029/030 leave general privileged assignment/MFA policy unresolved. SSO and enterprise-wide break-glass are deferred. No new sensitive guest-data collection or privacy runtime is authorized. Business Date and Financial Period remain operationally NOT STARTED, so source readiness is not live readiness.
